# إعداد فارماء حاشي مع Firebase Realtime Database

## ما الذي تغير؟
تم استبدال واجهة ووظائف PharmAssist القديمة بتطبيق دليل أدوية فقط. أزيلت وظائف نقاط البيع والفواتير والمخزون والمشتريات والعملاء والتقارير وتسجيل الدخول القديم والنسخ الاحتياطي القديم.

## المزامنة
- يقرأ التطبيق الأدوية من المسار `/medicines` في Realtime Database.
- يحفظ آخر نسخة محلياً في SQLite.
- عند وصول تحديث من Firebase يستبدل النسخة المحلية بمعاملة واحدة.
- عند تعذر الاتصال يعرض البيانات المحلية الموجودة.

## خطوة إعداد Firebase المطلوبة قبل البناء
1. افتح Firebase Console ثم إعدادات المشروع > تطبيقاتك > أضف تطبيق Android.
2. استخدم معرف الحزمة: `com.pharmahashi.app`.
3. نزّل ملف `google-services.json`.
4. ضعه في `android/app/google-services.json`.
5. تأكد أن Realtime Database يحتوي على البيانات تحت `/medicines`، مثل `med_001`, `med_002`...
6. اضبط قواعد RTDB بحيث تسمح بالقراءة للتطبيق، وتمنع الكتابة العامة. اجعل الكتابة للمشرف المصرح له فقط.

## قواعد مبدئية للقراءة العامة ومنع الكتابة العامة
إذا كانت قاعدة الأدوية مخصصة للقراءة العامة، يمكن استخدام قواعد شبيهة بالتالي، مع تقييد الكتابة للمشرف عبر آلية موثوقة (مثل custom claims/قواعد مناسبة لمشروعك):

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "medicines": {
      ".read": true,
      ".write": "auth != null && auth.token.admin === true"
    }
  }
}
```

لا تمنح المستخدمين صلاحية كتابة عامة. يجب إعداد مطالبة `admin` من بيئة موثوقة باستخدام Firebase Admin SDK، وليس من التطبيق.

## البناء
بعد تثبيت Flutter وAndroid SDK وإضافة `google-services.json`:

```bash
flutter pub get
flutter build apk --release
```

## ملاحظات مهمة
- لم يتم تضمين `google-services.json` لأنه خاص بتطبيق Android الذي تنشئه في Firebase Console.
- لم أتمكن من تشغيل `flutter analyze` أو بناء APK في بيئة العمل الحالية لعدم توفر Flutter SDK.
- قاعدة الأدوية الحالية تحتوي حقولاً قد تكون ناقصة أو غير مراجعة علمياً؛ يعرض التطبيق تنبيهاً بذلك ولا يضيف جرعات أو معلومات علاجية من عنده.
- التطبيق حالياً قارئ ومزامن للأدوية؛ لوحة تحكم المشرف منفصلة عن هذا المشروع.
